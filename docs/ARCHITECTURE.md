# Zapret Desktop — архитектура v2

Актуально на 2026-11-10. Заменяет план от 6 ноября. Этот файл — источник правды для разработки; если задача ему противоречит, сначала обсуждаем и меняем этот файл.

## Коротко

Делаем меньше, но доводим до релиза. Сначала Windows с одной кнопкой и подбором стратегии под каждый сервис, потом роутеры, Android и macOS. Весь бэкенд на Rust. Go-сайдкар и свой userspace-движок убраны, iOS и zstats отложены.

## Что изменилось относительно плана от 6 ноября

| Было | Решение | Почему |
| --- | --- | --- |
| Go-сайдкар znet: пробы, бандлы, обновления | Убран, всё внутри `zapretd` на Rust | Пробы уже на Rust; второй рантайм и JSON-RPC — лишняя работа для двоих |
| zbuild на Go | Rust-CLI `crates/zbuild` | Парсер .bat должен быть один. Сейчас их два: `scripts/prepare_engines.py` и `engines/macos/cmd/batconv` |
| zdesync, свой Go-движок для Android/iOS | Не пишем, берём byedpi / ByeByeDPI | Готовый обход через VpnService уже есть; проверить лицензии |
| iOS, tvOS | Вне рамок | Только TestFlight/AltStore |
| zstats | После v1, opt-in | Сервер, приватность, юридические риски |
| Запоминание по сети (ASN + Wi-Fi) | После v1 | Не блокирует релиз |
| Linux-десктоп с GUI | Побочный продукт фазы 3, без GUI | |
| macOS со своим движком и UDP | Заморожен в `engines/macos` до фазы 5 | Главный пожиратель времени |
| Подбор и пробы в процессе Tauri | Переезжают в `zapretd` | Подбор должен идти при закрытом окне |
| Отдельный демон на Go для macOS | Один `zapretd` на Rust; Go-движок Mac — внешний бинарник, как winws | Одна логика и один API |

Остаётся: демон с правами + GUI без прав, один `trait Engine`, компилятор стратегий с golden-тестами, подбор по сервисам с композитом через `--new`, свой hostlist поверх flowseal, подписанный канал бандла, Svelte-интерфейс, который на роутере работает как web UI.

## Порядок платформ

1. **Windows 10/11 x64** — winws + WinDivert, flowseal без изменений.
2. **Роутеры (OpenWrt, Keenetic)** — nfqws + nftables/iptables, тот же демон, тот же интерфейс в браузере. Linux-десктоп (systemd) получаем почти даром.
3. **Android и Android TV без root** — Kotlin VpnService + byedpi.
4. **macOS** — движок из `engines/macos` как адаптер `zapretd`, launchd, нотаризация.

Не делаем: iOS/tvOS; Tizen/webOS (закрывает роутер); Windows ARM64 до v1.

```

 ui/ + транспорт tauri              тот же ui/ + транспорт http
          │ named pipe / unix socket        │ HTTP + токен, только LAN
          └──────────────┬──────────────────┘
                         ▼
 ┌──────────── zapretd (root / SYSTEM) ────────────┐        Релиз flowseal
 │ API · Состояние · Selector · Doctor · Пробы ·   │              ▼
 │ Обновления ◄─────────────────────────────────────┼──── zbuild (GitHub Actions)
 │ zapret-core: компилятор стратегий, подпись,     │              ▼
 │              логика подбора                      │     Бандл: стратегии, списки,
 │ trait Engine: один движок за раз                 │     бинарники, подпись ed25519
 └──────┬───────────────┬───────────────┬──────────┘
        ▼               ▼               ▼
```

Android (фаза 4) живёт отдельно: роль демона играет VpnService, движок — byedpi.

| Компонент | Язык | Что делает | Фаза |
| --- | --- | --- | --- |

| `crates/zapretd` | Rust | Служба root/SYSTEM: API, состояние, ровно один движок, Selector, Doctor, обновления, чистка фаервола | 0–1 |

| `crates/zbuild` | Rust CLI | В CI: релиз flowseal → парсинг → сборка и подпись бандла. Не распарсилось — не публикуем | 1 |
| `src-tauri` | Rust | Тонкая оболочка: окно, трей, пересылка вызовов в демон, сохранение файлов по диалогу | 0 |
| `ui` | Svelte 5 + TS | Один интерфейс для Tauri и web UI; транспорт `tauri` или `http` | 0–3 |
| Установщики | NSIS, opkg, pkg | Windows со службой; пакеты роутеров; позже .pkg | 1/3/5 |
| Android | Kotlin + byedpi | VpnService | 4 |
| `engines/macos` | Go | Замороженный форк движка | 5 |

Контракты: источник правды — Rust-типы. `contracts/*.schema.json` (через `schemars`) и `ui/src/generated/*.ts` (через `ts-rs`) генерируются; CI падает, если сгенерированное устарело. Руками не правим.

## API демона

Один набор команд для всех транспортов: `snapshot` (статус + операция), `enable`, `disable`, `set_strategy`, `diagnose` (пробы), `select_strategy` (подбор), `cancel_operation`, `doctor`, `add_domain`, `logs`, `report` (возвращает JSON отчёта; файл пишет GUI в путь из диалога, демон в пользовательские пути не пишет). Команды фиксированные, никаких путей к исполняемым файлам и shell-строк. На роутере HTTP слушает только LAN и требует токен.

## Подбор и Doctor (v1)

Подбор («Проверить всё»), целиком в демоне:
1. Диагностика без обхода по сервисам из `targets.json`: подмена DNS, блок по IP, DPI по SNI, обрыв на 16–20 КБ, дроп QUIC. DNS → предложить DoH. Блок по IP → честно сказать, что не поможем.
2. Кандидаты — стратегии бандла в порядке flowseal.
3. По одному: запустить движок → дождаться готовности → параллельные пробы (~6 с) → остановить.
4. Кандидат дважды прошёл все сервисы → победитель.
5. Никто не прошёл всё → лучший профиль на каждый сервис, склейка через `--new` с хостлистом сервиса, проверка композита целиком.
6. Сохранить победителя; при отмене или провале вернуть исходную настройку.

Doctor: кнопка «не работает сайт», лёгкая проба раз в 10 минут, смена сети. Шаги: интернет/движок/конфликты (GoodbyeDPI, чужой WinDivert, VPN) → перезапуск движка → новый бандл → переподбор только сломавшегося сервиса → предложить добавить домен → отчёт без IP и истории.

## Обновления и подписи

- Бандл (фаза 1): манифест ed25519, ключ вшит в клиент, зеркала недоверенные (GitHub Releases + запасные). Предыдущий бандл хранится для отката.
- Приложение (фаза 2): скачать → проверить подпись → положить рядом → перезапустить службу → health-check → откат.
- Authenticode до публичной беты, нотаризация Mac в фазе 5. Ключи и платные сервисы — только решением владельца.
- Установка Windows — инсталлятор из GitHub Releases; роутеры — одна команда opkg.
